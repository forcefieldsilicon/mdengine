Analysis tools

One catalogue of studies — in the inspector, in the shell, and to an agent. ← back to the User Manual

How the catalogue is organised

An analysis tool is one study you run on one frame: it returns a summary table, optionally a per-atom field, a binned profile, one scalar worth plotting over time, and notes (caveats such as “preview, 1/4 of atoms”). Every tool — built in today, scripted later — returns that same shape, which is why the inspector, the CSV export, the CLI and the MCP server each need only one renderer.

Tools are grouped by the use case you arrived with, not by the maths: Surfaces & deposition, Adhesion & binding, Mechanics & deformation, Structure & order, Rendering & export. What a tool produces is shown as function badges, and badges are what compose: anything with profile draws a chart, anything with perAtomField can colour the atoms, anything with timeSeries can be swept across frames.

BadgeMeans
perAtomField One number per atom — drives the colour overlay and its legend.
profile A binned curve along an axis (bin edges, values, counts) — the chart, and the CSV.
scalar The single number worth watching (max penetration, mean charge…).
timeSeries That scalar is meaningful frame after frame, so it can be swept.

A tool also declares what it requires — a periodic box, a reference (t=0) frame, atom groups, or a side file. A tool whose requirement the data cannot meet greys out rather than returning a number that is quietly wrong.

Agent playbooks: every tool has a skill file at skills/tools/<id>/SKILL.md (decisions, parameters, how to run, how to read the result, caveats, pointers) and there are subject skills for MD-AFM adhesion, the MD→DFT→MLIP accuracy loop and potential selection under skills/. The MCP analyze catalogue returns the skill and manual path per tool.

Running a tool

In the app (inspector, phase 0c — the Tools area is landing now; described here as designed): Inspector ▸ Tools lists the catalogue by category. You enable a tool to add it to the frame's pass, and expand it to compute and read its results — an enabled tool that is collapsed still contributes its overlay, and nothing is computed for a tool you never enabled. Results update live while scrubbing, during playback, and as a followed file grows; during playback a cost governor may defer an expensive tool, and tools that support a strided preview can run on a subset of atoms while you drag (the result says so in its notes). A tool with a per-atom field can drive the viewport overlay and its legend; a tool with a profile draws a chart; every tool exports to CSV or to an Excel workbook (Summary, Profile, Series and — up to 100 000 atoms — the per-atom Field as sheets; the .xlsx is written in-process, no system zip), and the current view snapshots to PNG through the same Metal renderer as render_image.

In the shell and to an agent the catalogue is the same, with the same parameters and the same numbers:

mdengine analyze                                   # the catalogue as a table
mdengine analyze z_profile dump.lammpstrj --frame last
mdengine analyze column_field dump.lammpstrj --param column=c_pe --param bins=40
mdengine analyze z_profile dump.lammpstrj --all --csv depth.csv
mdengine analyze column_field dump.lammpstrj --frames 0-200:10 --json

Options: --frame first|last|N (default last), --all or --frames a-b[:stride] for a time series, --param key=value (repeatable; values are typed as int, float, true/false, else string) or --params '{"bins":40}' for nested parameters, --json for the raw result, --csv out.csv for the summary rows, then the profile bins, then one row per frame.

Agents reach the identical surface through the MCP tool analyze: call it without tool to get the catalogue (ids, categories, badges, requirements, default parameters), then with {tool, path, frame | frames, params} for the result as JSON. Per-atom field values are omitted unless include_field: true is passed — one float per atom is megabytes of transcript — so by default you get the palette, the legend title and the atom count. Parameters are merged over the tool's defaults; a value a tool cannot decode falls back to that tool's default for the field.

z_profile — Z-profile

profilescalartimeSeries Surfaces & deposition · no requirements · strided preview supported

Method

Depth analysis of a deposition or oxidation frame. Two species are chosen — the substrate (the slab) and the probe (the deposited species); by default the most abundant element and the second most abundant. The surface plane is the mean z of the top 5% of substrate atoms, which is robust against a few strays and against roughness in a way the single highest atom is not (that atom's z is reported alongside, so you can see the difference). Probe atoms are then classified against that plane: penetrated (below it, with min/mean/max depth), at surface (within 2.5 Å above it), and above (still in flight). When the file carries charges, the mean charge of bound probes is reported. The profile bins probe atoms by z − surface; bin width is max(0.5 Å, range/bins) and the last bin is closed at the top, so the highest atom is never dropped. The scalar is the maximum penetration (0 when nothing has penetrated).

Parameters

NameTypeDefaultMeaning

probestring or nullnull Deposited species. Null = the second most abundant.
binsinteger12 Requested bin count for the depth histogram (the 0.5 Å floor can yield more).
profileOfobject{"kind":"composition"} What the bins hold: composition = probe-atom counts; charge = mean probe charge per bin; {"kind":"field","name":"c_pe"} = mean of that per-atom column per bin (falls back to counts, with a note, when the frame has no such column).

Nested values like profileOf need --params '{"profileOf":{"kind":"charge"}}' — --param sets top-level keys only.

Reference

Depth-resolved profiles along the surface normal are the standard reading of a deposition or oxidation trajectory; the specific surface-plane definition here (mean z of the top 5% of substrate atoms, chemisorbed band 2.5 Å) is MDEngine's own convention rather than a standard — report it with the numbers. The implementation is Sources/LAMMPSCore/Analysis/ZProfileTool.swift, which wraps the app's original ZProfileAnalysis unchanged, with the bin geometry in Binning.swift. The MCP z_profile tool is the same analysis with a text readout and is kept for compatibility; analyze is where new parameters appear.

Validation

End-to-end: scripts/smoke_analyze.sh.

column_field — Colour by column

perAtomFieldprofilescalartimeSeries Rendering & export · no requirements · strided preview supported

Method

Colours atoms by any per-atom quantity the frame carries: a coordinate (x, y, z), the charge (charge, when the file has q), or any numeric column a LAMMPS dump or extended-XYZ brought along (c_pe, vx, …). One pass over the atoms gives min, mean, max and standard deviation; the colour range is the frame's own min…max unless you pin it (pin it when comparing frames — an auto range re-scales every frame). The field is published with a continuous palette and a legend title, and a second pass bins the same quantity along an axis, so the chart shows its mean versus depth. The scalar is the mean. Asking for a column the frame does not have is an error that lists the columns it does have.

adhesion — Adhesion

fieldscalartimeSeries Adhesion & binding · needs groups · no strided preview

Method

Two groups, A (receptor / substrate) and B (ligand / probe), are selected by extended-XYZ labels (chain, then resname), by element sets, or by a spatial slab; with no explicit selectors the two most populous chains (else residue names, else elements) are used and the choice is written into the notes. Contacts are heavy-atom A–B pairs closer than the cutoff (4.5 Å, the usual protein contact criterion), each pair counted once, via the shared cell-list neighbour finder. Hydrogen bonds follow Baker & Hubbard: donor N/O with a bonded H (H within 1.2 Å), acceptor N/O of the other group, D···A < 3.5 Å and D–H···A > 120°, counted in both directions; a frame without hydrogens reports polar N/O–N/O contacts by distance only and says so. Separation is the mass-weighted COM–COM distance (minimum image when a box exists) and the minimum interface distance. With resname + resid labels the five A residues with most contacts are listed — the "where does it stick" map. The per-atom field marks atoms in contact (A orange, B cyan) for the overlay. The scalar is the contact count, so the chart over frames is the binding history; ruptureFrame = the first frame from which contacts stay at zero.

Interaction fingerprint

Contacts say how much interface there is; the fingerprint says what holds it. It is name-based chemistry, so it needs the extended XYZ's name column (PDB atom name) alongside chain, resname and resid — smd_pull.py writes all four. Without name the tool reports contacts and H-bonds only and says so in the notes rather than guessing. Criteria are the conventional ones (PLIP / Arpeggio family):

InteractionCriterion
Salt bridge Cationic N (LYS NZ, ARG NH1/NH2/NE, HIS/HIP ND1/NE2) to anionic O (ASP OD1/OD2, GLU OE1/OE2, any OXT) closer than saltBridgeCutoff (4.0 Å). One residue pair counts once, however many atom pairs qualify.
π-stacking Aromatic rings (PHE, TYR, TRP — both rings, HIS): centroids < 5.5 Å apart, and either inter-plane angle < 30° with lateral offset < 2.0 Å (face-to-face) or 60–90° (T-shaped). Both types are reported separately. The ring normal is the best-conditioned centroid-relative cross product, so atom order in the file cannot flip it.
Cation–π LYS NZ or ARG CZ within 6.0 Å of a ring centroid of the other group.
Hydrophobic A side-chain carbon (CB onward) of ALA VAL LEU ILE MET PHE TRP PRO TYR within 4.0 Å of a carbon of the other group; residue pair counted once.

The per-atom field switches with quantity: "contacts" (the default, 0 none / 1 A / 2 B) or "interactions" — 0 none, 1 contact A, 2 contact B, 3 H-bond partner, 4 salt bridge, 5 π-stack or cation–π, 6 hydrophobic. An atom that qualifies for several takes the most specific: salt bridge > π > H-bond > hydrophobic > contact. Below the contact rows a per-residue table lists the eight group-A residues with most interactions, broken down by type.

Occupancy and lifetimes

With a whole trajectory loaded (lifetimes, default true) the tool also reports, over every frame: H-bond occupancy — the fraction of frames each donor–acceptor pair is bonded — and mean lifetime, the mean length of a continuous bonded run times the frame interval (from report_interval_ps in config.json; in frames, labelled as such, when no interval is known), top ten pairs by occupancy; and contact frequency per group-A residue. That table replaces "which residues touch in this one frame" with the question the study actually asks. The walk is O(frames × atoms), so it is cached per trajectory generation plus parameters and polls cancellation between frames — the app expands the section, and only then is it paid for, once.

MM/GBSA side files

When mmgbsa.py (delivery module 1) has been run over the same trajectory, its two CSVs are picked up beside the trajectory — the same search force_curve.csv uses (next to it, a results*/ sibling, or the run directory above). mmgbsa.csv adds ΔGbind for the current frame plus mean ± sd over the file, and its vdW / electrostatic / solvation split; interaction_energy.csv adds ΔEvdW and ΔEelec per receptor residue (top eight by |E|). Both are optional, both are read CRLF-safely and cached by path + mtime, and every result that quotes a ΔG carries the note that single-trajectory MM/GBSA without an entropy term is a rank-order estimate, not a binding free energy.

Reference

Salentin, S. et al. (2015) PLIP, Nucleic Acids Res. 43, W443 — interaction criteria. Gallivan & Dougherty (1999) PNAS 96, 9459 — cation–π. Genheden & Ryde (2015) Expert Opin. Drug Discov. 10, 449 — what MM/GBSA can and cannot be asked.

deformation — Deformation

fieldprofilescalartimeSeries Mechanics & deformation · needs a reference frame · no strided preview

Method

Per-atom deformation against a reference frame (frame 0 by default; the inspector has a picker and Use current). For each atom the neighbours within the cutoff are taken in the reference frame; from the reference separations d⁰ and current separations d the local deformation gradient F is the least-squares affine map (Falk & Langer 1998, in the formulation of Shimizu, Ogata & Li 2007 used by OVITO's Atomic Strain). From F: the Green–Lagrangian strain E = ½(FᵀF − I); volumetric strain tr(E)/3 and volume change det F − 1; von Mises shear strain; and D²min, the mean squared non-affine residual — the marker of plastic rearrangement and shear-transformation zones. Displacement magnitude and MSD use the minimum image under the current box, so a wrapped periodic trajectory does not fake large jumps. Atoms with fewer than three non-coplanar reference neighbours get no fit and are counted. When the dump carries six per-atom stress columns (c_stress[1..6] or sxx…syz) the von Mises stress is reported too. Box strain is given when both frames have a box. The field shown is chosen by quantity; rearranged is the categorical D²min > threshold map.

Parameters

NameTypeDefaultMeaning
cutoffÅ3.5Neighbour cutoff in the reference frame.
quantitystringshear shear · volumetric · d2min · displacement · rearranged · vonmises_stress.
d2minThresholdÅ²0.5Above = rearranged.
stressColumnsbooltrueRead per-atom stress columns when present.
profileAxis, binsx|y|z, integerz, 24Profile of the field along an axis.

MCP: reference_frame; CLI: --reference N.

Reference

Falk, M. L. & Langer, J. S. (1998) Phys. Rev. E 57, 7192 — D²min and the affine fit. Shimizu, F., Ogata, S. & Li, J. (2007) Mater. Trans. 48, 2923 — atomic strain from F.

Validation

Analytic fixtures on a 500-atom fcc block: uniform F = diag(1.02, 1, 0.99) and a 3 % simple shear reproduce the analytic strains with D²min ≈ 0; a rigid translation (wrapped through the periodic box) and a 10° rotation give zero strain and zero D²min; a single displaced atom lights up only its neighbourhood; hand-made uniaxial stress columns give the expected von Mises stress. Implementation note: the fitted matrix V⁻¹W is the transpose of F for row-vector conventions; the tool uses the true gradient so that d ≈ F d⁰ holds and rotations are strain-free.

crystallinity — Crystallinity

perAtomFieldprofilescalartimeSeries Structure & order · no requirements · strided preview supported

Method

Two readings of the same neighbourhood, both computed on every call.

Adaptive common neighbour analysis (a-CNA) gives each atom a discrete structure label — FCC, HCP, BCC, icosahedral or other — with no cutoff to tune. For each atom the 14 nearest neighbours are taken (search radius = 1.5 × the mean twelfth-neighbour distance, sampled from ~200 atoms, which is the smallest factor that always contains the fourteenth neighbour of an fcc lattice). The close-packed test uses the first twelve with the bond cutoff

r_c(fcc,hcp,ico) = (1 + √2)/2 · ⟨r₁ … r₁₂⟩

and, if that fails, the bcc test uses all fourteen — eight first neighbours at √3·a/2 and six second neighbours at a — with

r_c(bcc) = (1 + √2)/2 · ½ · ( 2·⟨r₁ … r₈⟩/√3  +  ⟨r₉ … r₁₄⟩ )

Both cutoffs estimate the conventional lattice parameter from the neighbour distances and then apply the classic factor (1+√2)/2, which puts the cutoff midway between the first and second shells of the lattice being tested; the bcc form simply averages the two independent estimates of a that the eight first and six second neighbours provide. A signature (common neighbours, bonds among them, largest connected bond group) is computed for every bond, and the multiset of signatures is matched exactly: fcc = 12 × 421, hcp = 6 × 421 + 6 × 422, bcc = 8 × 666 + 6 × 444, icosahedral = 12 × 555, anything else = other. The third index follows OVITO's definition — the number of bonds in the largest connected cluster of those bonds, not a longest simple path.

Averaged Steinhardt order gives the continuous companion, so “amorphous” is a number and not just the leftover bucket: qlm(i) is the mean of the spherical harmonics over the twelve nearest bonds, q̄lm(i) then averages qlm over i and its own neighbours, and q̄l = √(4π/(2l+1) · Σm|q̄lm|²) for l = 4 and 6. The harmonics are computed from the associated Legendre recurrences directly — no external dependency and no lookup table. Perfect fcc gives q̄₆ ≈ 0.575 and q̄₄ ≈ 0.191; a liquid sits near 0.3.

The summary reports the structure fractions, the crystalline fraction, the amorphicity index (= the “other” fraction, i.e. 1 − crystalline) and the mean q̄₆ / q̄₄. method decides only which quantity colours the atoms and which definition of “crystalline” drives the fraction, the profile and the scalar: acna = not “other”, q6 = q̄₆ above q6Threshold. The profile bins that 0/1 crystallinity along profileAxis — the “where is the oxide, where is the metal” reading — and the scalar is the crystalline fraction, which is what a time series plots across an anneal or an oxidation run.

No box is required: CNA is local. Without a cell the outer surface of an open block classifies as “other” (an incomplete neighbourhood is genuinely not fcc) and the result carries a note saying so. With a cell, distances use the minimum image, so a fully periodic crystal is 100 % classified with no surface. Giving cutoff a value switches to conventional CNA with that fixed bond cutoff: the neighbour set becomes everything inside the cutoff, and only 12- or 14-coordinated atoms can match a signature.

pulloff_energetics — Pull-off energetics

scalartimeSeries Adhesion & binding · needs a side file (force_curve.csv) · no strided preview

Method

This tool reads the pull-off protocol's force curve, not the atoms: the force_curve.csv written by smd_pull.py (time, reference displacement, ligand-COM displacement, spring force, running work, contacts), found next to the trajectory, in a results*/ sibling, or one level up when the trajectory sits inside results*/; config.json supplies the pull velocity and spring constant. Row i is aligned with frame i (the protocol writes both at the same cadence); frameAlignment: "time" aligns by time_ps instead. Per frame it reports the row's values plus the run-level numbers: rupture force F* (peak spring force, with its frame), work of separation W (the protocol's running ∫F·dxref, with a trapezoid ∫F·dxCOM check), and the rupture frame (contacts → 0 and stay 0). With several seeds, F* and W are given as median [IQR] — distributions, never a bare mean. A Bell–Evans fit of F* against ln(loading rate) (koff⁰, xβ) appears only when runDirs supplies ≥ 3 distinct velocities; a Jarzynski / second-order-cumulant free energy only when ≥ 10 seeds were pulled at ≤ 1 Å/ns — otherwise the row says "work, single pull — not a free energy". The scalar is the spring force at the frame, and the result carries the whole force curve as a frame-indexed series, so the F(t) chart appears the moment the tool is added and its marker follows playback; click a point to jump to that frame. Every result carries the note that SMD loading rates are 10⁶–10⁹× AFM: F* is never an experimental number.

ptm — PTM (orientation & grains)

perAtomFieldprofilescalartimeSeries Structure & order · no requirements · strided preview supported

Method

Polyhedral template matching answers the same question as a-CNA — what structure is this atom in — but by least squares rather than by bond topology, and it returns two things a-CNA cannot: the orientation of the local lattice and its elastic distortion. Orientation is what turns “these atoms are fcc” into “these atoms are two grains meeting at 15°”.

For each atom the N nearest neighbours are taken — 12 for fcc/hcp/icosahedral, 14 for bcc (8 ⟨111⟩ + 6 ⟨100⟩), 6 for simple cubic — and scaled by their mean length. Each candidate template is the ideal neighbour shell of that structure, also at unit mean length. Following the paper the point set is the N neighbours and the central atom, both sides shifted to their own centroid, and the tool minimises

RMSD = √( 1/(N+1) · [ Σᵢ |bᵢ − b̄ − R·a_π(i)|²  +  |b̄|² ] )

over the correspondence π (which neighbour sits on which template vertex) and the rotation R. Centring is not cosmetic: the displacement of the central atom is common to all N measured vectors, so leaving it in would put it into every residual and inflate the RMSD by √2 on a hot frame.

The correspondence is found geometrically. A seed maps the atom's nearest neighbour to a template vertex and its first non-collinear neighbour to another, keeping only pairs whose template angle is within 15° of the measured one. The rotation follows from Horn's quaternion method — the dominant eigenvector of a symmetric 4×4, found by cyclic Jacobi, so there is no SVD in the codebase at all. Every remaining neighbour then takes its nearest template vertex (a collision falls back to a globally greedy matching), and the best two seeds get two assign → Kabsch rounds each. The smallest RMSD over all templates wins; below rmsdThreshold the atom takes that template's structure, above it the atom is other.

This is PTM's RMSD and orientation, without the paper's Weinberg canonical-form acceleration, which turns the correspondence search into a graph-hash lookup. The trade is deliberate: a short port you can check by eye instead of a fast one you cannot. The one economy taken is exact — applying a symmetry of the template to a correspondence gives another correspondence with the same RMSD, so the search only needs to seed on one vertex per orbit of the template's proper rotation group (one for fcc, ico and simple cubic; two for bcc and hcp) instead of on all 12 or 14.

Grain boundaries. The disorientation between two atoms is the angle of q₁⁻¹q₂ minimised over the lattice's proper rotation group — 24 operations for fcc/bcc/simple cubic, 12 (D₆) for hcp, none for icosahedral. One-sided reduction is exact here, not an approximation: rotation angle is invariant under conjugation, so the two-sided class {g₁Mg₂} produces exactly the angles {angle(gM)}. An atom with any same-type neighbour disorientation above gbAngle is flagged a grain-boundary atom; atoms joined by a disorientation below it are unioned, and the number of connected clusters of 4 atoms or more is reported as the grain count. The comparison runs over every neighbour inside the structure-search radius, not only the template's own vertices: at a sharp boundary the atoms on the interface match no template at all, so the last matched atom of one grain and the first of the other are two shells apart and a 12-nearest test would look straight past the boundary it is meant to find.

Strain. The matched correspondence also gives the affine fit F = (Σ bᵢaᵀ)(Σ aaᵀ)⁻¹ with b ≈ F a. Since both sides carry unit mean neighbour length the volumetric part is divided out, so the reported von Mises invariant of ½(FᵀF − I) is the deviatoric (shear) distortion only.

Orientation colouring is published as a single hue in 0…1, not as a colour triple, because a per-atom field is one number. For cubic structures it is the inverse-pole-figure hue of the crystal direction parallel to the lab z axis, folded into the standard triangle and weighted barycentrically — 0 = red = ⟨001⟩, ⅓ = green = ⟨101⟩, ⅔ = blue = ⟨111⟩. hcp has no such triangle, so it uses the simpler scheme of the c-axis tilt away from z (0 = c ∥ z, 1 = c ⟂ z), and the result says so in a note. That is roughly two orders of magnitude above a-CNA and is the price of the missing canonical-form lookup; estimatedCost reports it so the governor defers the tool during playback rather than dropping frames.

Validation

PTMToolTests checks the algebra first: Horn's method recovers known rotations (including from only two vector pairs) to 1e-9 rad, the quaternion and its matrix rotate identically, and disorientation reduces 90° about ⟨001⟩ and 120° about ⟨111⟩ to zero under cubic symmetry while leaving 3° at 3°.

On the synthetic lattices of Tests/AppTests/Fixtures.swift, perfect fcc (Al), bcc (Fe) and hcp (Mg) each come out 100 % of the right type with mean RMSD below 1e-6, one grain and no grain-boundary atoms. An fcc block turned 20° about ⟨110⟩ returns that orientation to within 0.5° modulo cubic symmetry, and an unturned one returns the identity. A bicrystal — two fcc half-blocks meeting at x = L/2 with the right one turned 15° about z, open in x and y so no wrap seam can pose as a boundary — gives exactly two grains, with every flagged atom inside one lattice spacing of the interface and a mean disorientation that reads as high-angle (~13°, pulled below 15° because the last matched atoms on each side sit in the boundary's strain field).

The phase-plan gate is the hot frame: an fcc block shaken by an independent Gaussian of σ = 0.15 Å (~5 % of the 2.86 Å nearest-neighbour distance) must come out ≥ 95 % fcc under PTM and must beat a-CNA on the same frame — it does, 95.3 % against 90.6 %. Note that independent per-atom noise is a harsher test of relative geometry than a real hot crystal, whose displacements are dominated by long-wavelength phonons that move neighbours together; the σ that breaks this fixture is well below the σ that would break a thermalised frame. Past σ ≈ 0.2 Å the hard RMSD cut makes PTM fall off faster than a-CNA's topological test, which is worth remembering before raising the temperature: raise rmsdThreshold with it. A σ = 0.6 Å frame (a liquid) comes out under 10 % crystalline. Profile, strided preview, the unknown-quantity fallback and cancellation are covered too.

grains — Grain boundaries

perAtomFieldprofilescalartimeSeries Structure & order · no requirements · strided preview supported

Method

PTM answers “what structure is this atom in, and how is its lattice turned”. This tool asks the question a deposited film or an annealed sample actually raises: how many grains, how big, how much of the solid is boundary, and what misorientations do those boundaries carry. The orientations come from exactly the same code — the classification and the segmentation are shared with ptm (GrainSegmentation.swift), so the two tools cannot drift apart.

Three steps. (1) Cluster. Atoms that match a template are unioned with every same-structure neighbour whose symmetry-reduced disorientation is under gbAngle; clusters below minimumGrainSize atoms are dropped. (2) Contact. A sharp high-angle boundary is a layer of atoms that match no template, so the two crystals never see each other and a neighbour-to-neighbour test finds nothing. The tool therefore walks the contacts through that layer: an atom touching two different clusters at once is a grain-boundary atom, and the angle it sits on is the disorientation between the two clusters it bridges. Low-angle boundaries, where the atoms stay matched across the interface, are caught by the direct test as before. (3) Merge. Two clusters that meet at less than gbAngle are one grain that a defect layer happened to cut in two, so they are merged before anything is counted. Grains are then numbered 1…K largest first.

Grain size is reported in atoms and, when the frame has a box, as the equivalent spherical diameter of the grain's share of the cell volume, d = 2·(3·N·v/4π)⅓ with v = Vcell/Natoms. With a large vacuum or gas region in the box that v is too big and the diameter is an overestimate; the result says so in a note.

Parameters

NameTypeDefaultMeaning
quantity "grain"/"gb"/"misorientation" "grain" What colours the atoms. grain = the grain id as a categorical colour (0 = boundary or unassigned, grey; up to 23 grains get a legend, above that the id is shown as a ramp); gb = interior grey / boundary orange; misorientation = degrees, the largest disorientation to any same-structure neighbour, so an interior atom reads ~0 and a boundary atom carries the angle of the boundary it sits on.
gbAnglenumber (degrees)5.0 Disorientation that separates two grains — the clustering cut, and the cut below which two touching clusters are merged back into one.

Reading the result

Grain count (the scalar, so it plots straight over frames — grain growth is a falling count), grain-boundary atom fraction, crystalline fraction, mean and median grain size in atoms and in Å, mean misorientation over the boundary contacts, and the number of those contacts. The profile is the misorientation distribution function unless an axis is asked for.

Validation

GrainBoundaryToolTests runs synthetic polycrystals: slabs of Al fcc cut from one lattice and turned about z, periodic in z (a z rotation keeps the lattice periodic along z but not along x or y, so those faces stay open and no wrap seam can pose as a boundary). A perfect crystal gives one grain, no boundary atoms and a diameter equal to the box read as a sphere. A bicrystal turned 30° gives exactly two grains, a mean misorientation of 30° ± 2°, a boundary fraction of a few percent, and every flagged atom within 1.5 lattice spacings of the interface plane; the distribution peaks in the 30° bin. A tricrystal (0°, 20°, 40°) gives three. Shaking every atom by a Gaussian of 2 % of the nearest-neighbour distance changes neither the grain count nor the mean angle. conformation — Conformation (RMSD · Rg · DSSP · clusters)

perAtomFieldscalartimeSeries Structure & order · no requirements · no strided preview (a global fit on a subset of atoms would move the answer)

Method

The biomolecular counterpart of deformation: instead of a local affine fit it asks global questions about a whole trajectory. Every comparison first removes the tumbling by optimal superposition on the chosen atoms (Kabsch's rotation, computed in Horn's quaternion form — the largest eigenvector of a 4 × 4 built from the correlation matrix, which cannot fall into the reflection that a naive SVD implementation returns).

Per frame: RMSD to the reference frame after that fit (the RMSD without the fit is reported alongside, so rigid drift is visible), and the mass-weighted radius of gyration of the group. Over the trajectory, computed once and cached per trajectory generation and parameter set: RMSF per atom after superposing every frame on the reference, the mean structure, a clustering of frames by pairwise RMSD (each pair superposed on its own, not read off a common fit), and a PCA of the superposed coordinates — the leading eigenvectors of the coordinate covariance by power iteration with deflation, so the 3N × 3N covariance is never formed. The summary gives the variance each component explains and the projection of the current frame on PC1/PC2.

Clustering is either k-medoids (deterministic: farthest-point seeding, then assign / re-medoid until nothing moves — no RNG, so the same trajectory clusters the same way twice) or, when clusterRMSDCutoff is set, gromos-style cutoff clustering (Daura 1999): take the frame with the most neighbours within the cutoff as a centre, remove it and its neighbours, repeat — the cluster count comes out of the data. Clusters are renumbered so cluster 1 is the most populated. Above 400 frames the distance matrix is built from every k-th frame and the remaining frames are assigned to the nearest medoid; the result says so in its notes.

Secondary structure (the dssp field) is DSSP as Kabsch & Sander defined it: residues are grouped by chain and residue id from the extended-XYZ name/chain/resid columns, the amide hydrogen is reconstructed at H = N + (Cprev − Oprev)/|Cprev − Oprev| × 1 Å, and a hydrogen bond is an electrostatic energy E = 0.084 · 332 · (1/rON + 1/rCH − 1/rOH − 1/rCN) below −0.5 kcal/mol. From the bond map: n-turns (n = 3, 4, 5), minimal helices from two consecutive turns (H for 4, G for 3, I for 5), parallel and antiparallel bridges collected into ladders (E; an isolated bridge is B), T for the remaining turn residues, S for a bend (κ > 70°), else coil. Turns, helices and bends are confined to an unbroken backbone segment, so two chains laid side by side never fake a turn across the gap. A frame with no name column cannot be assigned — the tool says “DSSP needs atom names (extended XYZ name column)” rather than guessing that a C is a Cα.

The selection is by atom name: ca, backbone (N, CA, C, O), heavy (everything but hydrogen) or all; on a frame with no name column, ca and backbone fall back to heavy atoms and note it. The scalar is the RMSD, so sweeping frames plots the familiar RMSD-vs-time curve.

Parameters

NameTypeDefaultMeaning

quantitystringrmsf Field shown: rmsf · dssp · displacement (from the reference, after the fit).

The reference is the frame the inspector's reference picker holds (MCP reference_frame, CLI --reference N), and frame 0 of the trajectory when none is set.

Reference

Kabsch, W. (1976) Acta Cryst. A32, 922 — the optimal rotation. Horn, B. K. P. (1987) J. Opt. Soc. Am. A 4, 629 — its quaternion form. Kabsch, W. & Sander, C. (1983) Biopolymers 22, 2577 — DSSP. Daura, X. et al. (1999) Angew. Chem. Int. Ed. 38, 236 — gromos cutoff clustering.

Validation

Analytic fixtures. A rigidly rotated and translated copy of a 20-atom cloud fits back to RMSD 0 (10⁻⁹ Å) while the unfitted RMSD is several Å, and a weighted fit ignores an atom outside the weight set. A five-frame trajectory in which one atom wiggles by ±0.5 Å gives that atom RMSF 0.316 Å = √(2·0.25/5) and every other atom below 0.05 Å. Eight equal masses at the corners of a cube of half-edge d give Rg = d√3 exactly. Nine frames in three well-separated basins cluster 4/3/2 under both k-medoids and the gromos cutoff, and a 450-frame two-basin trajectory (over the 400-frame cap) still recovers 300/150 through the subsample-and-assign path. Frames displaced along a single direction put > 98 % of the variance on PC1, and the solver returns exactly one component with the closed-form variance for exactly rank-one data. Backbone fixtures are built from internal coordinates (NeRF) and checked against their own torsions: an ideal α-helix (φ = −57°, ψ = −47°, 12 residues) is 83 % H overall and 100 % H over the interior residues — the two termini cannot be helix, since a minimal helix needs two consecutive 4-turns; two ideal β-strands (φ = −120°, ψ = +130°) related by the sheet's two-fold axis at 4.85 Å are 62 % E, which is 5 of the 6 assignable residues in each strand. That sheet is an idealisation rather than a relaxed hairpin, so the test asserts ≥ 50 % E rather than a specific pattern. A frame with no name column returns no DSSP field and the note that says why.

rdf — Radial distribution

perAtomFieldprofilescalartimeSeries Structure & order · no requirements (a box is strongly recommended) · strided preview supported

Method

The pair correlation function g(r): how much more likely a B atom is at a distance r from an A atom than it would be in a structureless fluid of the same density. Pair separations up to rMax are collected from the shared neighbour list and binned, then each bin is divided by the ideal-gas expectation for that bin, NA·ρB·(4/3)π(rhi³ − rlo³) — the exact shell volume, not the thin-shell 4πr²dr, which is several per cent wrong in the first bins, exactly where the first peak is. With a cell, distances use the minimum image and ρB is NB/V; without one, ρ comes from the atoms' bounding box and the result carries a note saying so, because a bounding-box density is not comparable with anybody else's g(r). For a self-pair (A = B, or both unset) the density uses N − 1: an atom is not its own neighbour.

Two derived numbers follow. The first peak is the first local maximum of a five-bin moving average that is a real excess (g ≥ 1.2) over a bin with real statistics (≥ 10 pairs) — smoothing locates it, but the position reported is the raw bin, so smoothing never moves a shell. The first minimum is the bottom of the valley after it, and — unless coordinationCutoff overrides it — that is the radius the coordination number is counted inside, which is the standard convention, and the one that gives 12 for fcc without being told. The coordination pass rebuilds the neighbour list at that smaller radius rather than re-walking the rMax one; the cell grid is then (rMax/rc)³ times finer, which is the difference between visiting ten candidates per atom and a thousand. The per-atom field is the coordination number; the scalar is the first-peak position, so the chart over frames shows the first shell contracting or melting.

Parameters

NameTypeDefaultMeaning
speciesA, speciesBstring or nullnull Element of the central / neighbouring atoms; null = every atom. Partial gAB(r).
rMaxÅ10 Largest separation binned. Above half the shortest box edge the minimum image double-counts, and the tool says so.
binsinteger200 Bin count over [0, rMax]. Thin bins resolve sharp shells but need pairs: ~700 pairs per 0.05 Å bin is ±4 % of Poisson noise.
coordinationCutoffÅ or nullnull Radius for the coordination number; null = the first minimum of g(r), and the value used is reported.

Strided preview: 1/n of the A atoms are used as centres and the normalisation uses that count, so the curve is unbiased, only noisier.

Reference

Allen, M. P. & Tildesley, D. J. (2017) Computer Simulation of Liquids, 2nd ed., §2.6 and §5.6 — g(r), its ideal-gas normalisation and the coordination number as its running integral to the first minimum.

Validation

Two fixtures with an answer known before the code runs. 2000 uniform random atoms in a 40 Å periodic cell — the definition of no structure — give g(r) = 1 ± 0.15 over r ∈ [3, 8] Å and a coordination number inside 10 % of ρ·(4/3)πrc³ at rc = 5 Å. A perfect fcc block (a = 4.05 Å, 864 atoms) puts the first peak at 2.875 Å against the analytic a/√2 = 2.8638 Å (+0.39 %, one bin width at the default 200 bins) and gives exactly 12 neighbours at the first minimum, with no caveats emitted. An open-boundary slab reports the bounding-box note.

diffusion — Diffusion (MSD)

perAtomFieldscalartimeSeries Mechanics & deformation · needs a reference frame · strided preview supported

Method

Mean squared displacement against a reference frame, and the Einstein diffusion coefficient from its slope: MSD = 6·D·t in three dimensions. The factor is 2d, so a 1D or 2D reading of the same data would use 2 or 4 — the commonest way to be wrong by 3× about a diffusion coefficient is to disagree silently about it, so the summary row names the convention it used.

The other way to be wrong is wrapping. A periodic dump folds atoms back into the cell, so a raw r(t) − r(0) saturates at the box diagonal and D collapses towards zero at long times. With unwrap (on by default) the tool walks the whole trajectory once and accumulates the minimum-image step between consecutive frames, which is exact as long as no atom moves more than half a box in one dump interval — and when one does, the note says so and calls D a lower bound. That walk is a trajectory-level quantity, cached per trajectory generation and parameter set, so scrubbing through frames costs one array lookup. Time comes from the dump's own timestep × timestep_fs; frames with no timestep fall back to index × frameInterval_ps. The fit skips the first fitStartFraction of the series — the ballistic and caging head is not Fickian and would bias D upwards — and reports the ordinary-least-squares standard error of the slope alongside it, in Å²/ps and in cm²/s (1 Å²/ps = 10⁻²⁰ m² / 10⁻¹² s = 10⁻⁴ cm²/s). The per-atom field is |Δr|², the scalar is the MSD, so the chart over frames is the MSD curve itself.

Parameters

NameTypeDefaultMeaning
speciesstring or nullnullElement to follow; null = every atom.
timestep_fsfs1.0Femtoseconds per LAMMPS step; time = dump timestep × this.
frameInterval_psps1.0Used only when frames carry no timestep (plain XYZ).
fitStartFractionfraction0.2Fit D on the last 80 % of the series.
unwrapbooltrueUndo periodic wrapping between consecutive frames. Required for MSD in a periodic cell.

With only one frame loaded the MSD is still reported and D is not — the tool never fits a slope through a single point.

Reference

Allen, M. P. & Tildesley, D. J. (2017) Computer Simulation of Liquids, 2nd ed., §2.7 and §8.5 — the Einstein relation, the choice of fitting window, and why unwrapped coordinates are what the relation is written in.

Validation

A synthetic Gaussian random walk with a known answer: step width σ per component per frame gives MSD = 3σ²n = 6D(nΔt), so D = σ²/2Δt exactly. With σ = 0.4 Å, Δt = 1 ps and 30 frames of 6000 walkers wrapped into a 12 Å cell, the tool recovers D = 0.0792 Å²/ps against the analytic 0.08 (−0.98 %; every seed tried lands inside 1.3 %), and the MSD computed from the wrapped dump equals the MSD of the never-wrapped truth frame for frame to 10⁻⁹ Å². Adding a 0.5 Å/frame drift, so atoms cross the cell, drops the un-unwrapped MSD below 40 % of the truth — the failure this option exists to prevent. Sample size is part of the test: at 500 walkers the same estimator swings from −12.7 % to +5.6 % on the seed alone, which measures luck rather than the code.

thermo — Thermo (log.lammps)

scalartimeSeries Mechanics & deformation · needs a side file (log.lammps) · no strided preview

Method

Everything a run measures about itself as a whole — temperature, pressure, energies, box lengths, any compute or variable the deck put in a thermo_style custom line — is in the log and nowhere in the dump. This tool parses it and puts it beside the trajectory: scrub to a frame and read the row LAMMPS printed at that step. The parser is header-driven and forgiving — a block starts at a line whose first token is Step and ends at Loop time of …, one block per run, so a multi-run deck (equilibrate, then deform) gives several, and the deck may change thermo_style between them. Interleaved WARNING: lines, blank lines and the truncated tail of a log still being written are ignored rather than treated as the end of a table, and the split is on any newline because "\r\n" is one Swift character. Columns present in every block are the ones whose concatenated series stay row-aligned; anything else is named in a note rather than silently misaligned. Alignment to frames is alignBy: step matches the frame's timestep to the nearest Step row (a dump every 100 steps against thermo every 250 still lands), index is the naive row i ↔ frame i.

The second job is the mechanical test, which exists only here: per-atom stresses are optional and expensive, the box pressure is free and always printed. When the log carries a length (Lx/Ly/Lz, or a c_*/v_* alias) and the matching pressure (Pxx/Pyy/Pzz), the tool takes the axis whose strain changed most, computes engineering strain L(step)/L(step₀) − 1 and stress −P (LAMMPS prints pressure, and a positive pressure is compression), converts bar to GPa (×10⁻⁴), and fits Young's modulus over the first elasticStrain of strain travelled. The fit range is reported with the number, so a modulus read off a plastic segment is visible as one. The scalar is the stress at the frame when a curve resolved, else the first requested y column — either way the chart follows playback.

Validation

A hand-made log with two runs — equilibration at fixed length, then tension — a WARNING: line inside the first table and a full CRLF variant: both parse to the same two blocks with the same 5 and 16 rows, the same loop times, and identical results. The tension run is written as σ = E·ε with E = 70 GPa up to 2 % strain and a perfectly plastic plateau after; the tool recovers 70 GPa to better than 1 % from the default 2 % window, and reports the plateau as the maximum stress. A frame stamped step 900 reads the step-900 row (1 % strain, run 2 of 2) even when its frame index is deliberately wrong, and alignBy: "index" reads row i instead. A directory with no log throws missingRequirement(.sideFile).

Result shape

Every tool returns the same object, so --json and the MCP tool are the same document:

{
  "summary": [ { "label": "Surface plane z", "value": "12.897", "unit": "Å" }, … ],
  "field":   { "name": "z", "legendTitle": "z", "count": 4000,
               "palette": { "kind": "continuous", "min": 0.0, "max": 16.8,
                            "colormapName": "viridis" } },
  "profile": { "axisLabel": "z − surface (Å)", "valueLabel": "probe atoms",
               "edges": [ … n+1 … ], "values": [ … n … ], "counts": [ … n … ] },
  "scalar":  1.42,
  "notes":   [ "Preview: 1/4 of atoms." ]
}

field, profile and scalar are present only when the tool's badges say so, and field.values (one float per atom) appears only with include_field: true — otherwise count stands in for it. A time-series call replaces the whole document with {"tool": …, "frames": [{"frame": n, "scalar": …, "summary": [ … ]}, …]}.
